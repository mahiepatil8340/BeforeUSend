METHODS AND PRIVACY

Methodology and privacy

A concise summary of what the system does, what it does not do, and how user drafts are handled.

Methodology

How estimates are produced

Input fieldsMessage, communication goal, tone, recipient, and optional context
Language reviewPattern matching for escalation cues, requests, apologies, boundaries, and cooperative wording
ScoringFast estimates for escalation potential, goal alignment, and interpretation clarity
FeedbackHighlights, explanations, and an instant rewrite suggestion

Limitations

What the system cannot know

True intentThe system cannot know what the sender truly meant
Relationship historyScores can miss context that is not typed into the tool
Clinical meaningThe tool does not diagnose emotions, risk, or mental state
Ground truthScores are estimates, not measured probabilities

Privacy

Where analysis happens

  • Analysis and rewriting run in the browser.
  • The site does not intentionally send drafts to a remote analysis API.
  • No account is required to use the main review features.

Data handling

What users should assume

  • Anything typed into a browser can remain in browser memory while the page is open.
  • Standard browser caching behavior may apply.
  • Users should avoid entering sensitive information on shared devices.

PRIVACY BY DESIGN

Your message stays in your browser

Immediate message analysis and optional rewriting run in the browser; this deployment does not provide a server endpoint for receiving drafts, and it does not intentionally save message text to a database.

On-device interpretation

No remote text-analysis API in this build.

No account required

Drafts are not intentionally persisted by the app.
